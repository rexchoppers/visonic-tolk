# Visonic Tolk

Visonic Tolk is a Go rewrite of msp1974's
[visonic_proxy](https://github.com/msp1974/visonic_proxy). It sits between a
Visonic PowerMaster panel, Visonic's servers and Home Assistant.

## Background

The original has had no commits since May 2025.

## Features

- Each connection has its own acknowledgement gate, so a quiet panel does not
  hold up traffic to Home Assistant.
- Messages split across packets are reassembled, and several arriving together
  are separated by validating their checksums.
- Stealth mode drops the cloud link while Home Assistant reads the panel's
  EPROM, and restores it afterwards.
- The HTTPS certificate the panel needs is generated on first start.
- Every frame can be logged in and out as spaced hex for debugging.
- A 2.7 MB static binary with no interpreter and no dependencies.
- Output on the wire is byte for byte identical to the original, verified
  against test vectors generated by running it.

## Not supported

| | |
|---|---|
| Visonic's cloud servers | Untested. The connection opens, but nothing beyond that has been verified |
| Websocket mode | Socket mode only, as used by [davesmeghead/visonic](https://github.com/davesmeghead/visonic) |
| B0 shorthand | Refused and logged rather than guessed at |
| Command replay on reconnect | Visonic asks again on its own |

## Installing

1. Open Settings, then Apps, then the App Store
2. From the menu in the top right, choose Repositories and add
   `https://github.com/rexchoppers/visonic-tolk`
3. Check for updates, then install Visonic Tolk
4. Stop the original proxy first, as both use the same ports
5. Start it

Nothing needs changing on the panel, as the ports are the same. To roll back,
stop this and start the original again.

| Port | Used for |
|---|---|
| 5001 | The panel's message connection |
| 5002 | Home Assistant |
| 8443 | The panel's web check-in, which is what tells it to connect |

The certificate for port 8443 is generated on first start and kept in
`/data/certs`.

## Options

| Option | Default |
|---|---|
| `visonic_host` | `52.58.105.181` |
| `message_port` | `5001` |
| `alarm_monitor_port` | `5002` |
| `webserver_port` | `8443` |
| `visonic_reconnect_interval` | `10` |
| `keepalive_timer` | `32` |
| `watchdog_timeout` | `120` |
| `stealth_mode_timeout` | `10` |
| `ka_time` | `10` |
| `log_level` | `info` |

`ka_time` is how many seconds the panel is told to leave between check-ins. Ten
is what the original sends. Whether it paces anything else the panel does is
unknown.

Setting `log_level` to `debug` logs every frame in and out as spaced hex, which
can be compared directly against the original's log. Anything the proxy does not
understand is logged with the word `unsupported`.

## Status

This is early software. It runs against a single panel, mine, and has not been
tried on anyone else's setup. If something breaks, the log at debug level will
usually show which frame caused it.
